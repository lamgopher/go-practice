## Практика

### Задание 1. Модуль-библиотека и модуль-клиент

1. Создайте модуль `github.com/<you>/storage` со структурой каталогов из воркшопа:
   ```
   cmd/storage/main.go
   internal/file/file.go        // type File {ID uuid.UUID; Name string; Data []byte}, NewFile, String()
   internal/storage/storage.go  // Storage с приватной map, Upload(name, data) (*File, error), GetByID(id) (*File, error)
   ```

3. Из `main` попробуйте обратиться к приватной map хранилища — прочитайте ошибку.
4. Создайте рядом модуль `client` и попробуйте импортировать `.../storage/internal/storage`. Прочитайте ошибку.
5. Добавьте в библиотеку `pkg/storage` с публичной функцией-фасадом и используйте её из клиента. Пока библиотека не
   опубликована, подключите её через `replace` в `go.mod` клиента.

### Задание 3. defer / panic / recover

Прогноз, затем запуск:

```go
func a() {
    i := 1
    defer fmt.Println("defer 1:", i)
    i = 2
    defer func() { fmt.Println("defer 2:", i) }()
    i = 3
}

func b() (result int) {
    defer func() { result *= 2 }()
    return 21
}

func c() {
    defer fmt.Println("c: first")
    defer func() {
        if r := recover(); r != nil { fmt.Println("recovered:", r) }
    }()
    var s []int
    _ = s[5]
    fmt.Println("unreachable?")
}
```

Затем:

1. Напишите `SafeCall(f func()) (err error)`, превращающую панику в ошибку.
2. Напишите функцию копирования файла, где оба файла гарантированно закрываются через `defer`, а ошибка `Close`
   выходного файла не теряется.
3. Запустите панику в отдельной горутине при наличии `recover` в `main`. Что произойдёт? Почему?

### Задание 4. Бот шаг за шагом

Повторите путь воркшопа, коммитя каждый шаг отдельно (эталон — https://github.com/ozonmp/omp-bot):

1. Эхо-бот в одном `main.go`, токен из переменной окружения / `.env`.
2. Команда `/help` и обработчик по умолчанию, `switch` по `Command()`.
3. Пакет `internal/service/product` с `Service`, `Product{Title}`, `List()`; команда `/list`.
4. `Commander` в `internal/app/commands`: один файл на команду, `HandleUpdate(update)`, `main.go` только собирает зависимости.
5. `/get <id>` с разбором аргумента. Некорректный аргумент и несуществующий id не должны ронять бота: сервис
   возвращает ошибку, пользователь получает понятное сообщение, подробности — в лог.
6. `recover` в `HandleUpdate`, чтобы паника в одной команде не останавливала бота. Проверьте умышленной паникой.
7. Inline-кнопка «Next page» у `/list`: данные кнопки — JSON `{"offset": N}`; реализуйте постраничный вывод по 3 элемента.
8. Проверяйте ошибку `bot.Send` и логируйте её.
