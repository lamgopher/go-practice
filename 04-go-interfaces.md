# Занятие 04. Интерфейсы в Go

Видео: https://www.youtube.com/watch?v=ug8QDamBI7c (2:13:23), лектор — Даниил Подольский

Лекция на две трети «философская»: кода на слайдах мало, главное — зачем интерфейсы и где проходят границы их
применимости. Практика ниже восполняет отсутствие примеров.

## Вопросы для самопроверки

1. Что такое интерфейс в Go и чем он отличается от абстрактного класса?
2. Как компилятор понимает, что тип реализует интерфейс? В какой момент выполняется проверка?
3. Из чего состоит значение интерфейса во время выполнения?
4. Почему лектор против возврата интерфейса из конструктора приватной структуры?
5. Что такое ad-hoc полиморфизм и чем он отличается от параметрического?
6. Почему встраивание интерфейсов — не наследование? Что реально даёт `io.ReadWriter`?
7. Что такое coupling и чем плохо высокое зацепление? Как интерфейс его снижает?
8. Где следует объявлять интерфейс — рядом с реализацией или рядом с использованием? Почему?
9. Что делать, если один и тот же маленький интерфейс нужен в десяти пакетах?
10. Почему нельзя брать стандартную библиотеку за образец расположения интерфейсов?
11. Зачем выделять DAL в отдельный слой? Что лектор называет «отравлением» кода?
12. Почему даже при интерфейсах на стороне потребителя бизнес-логика остаётся привязанной к пакету DAL?
13. Почему `[]io.ReadWriter` нельзя передать туда, где ждут `[]io.Reader`?
14. Чем плох `interface{}` в сигнатурах? Какая альтернатива?
15. Чем `v := i.(T)` отличается от `v, ok := i.(T)`? Когда нужен type switch?
16. Как `encoding/json` и `sort` используют интерфейсы, реализованные вашим типом?
17. Объясните ловушку: функция возвращает `error`, внутри `var e *MyErr = nil; return e`, а проверка `err != nil` истинна.
18. Какой практический выигрыш интерфейсы дают в тестировании?
19. Почему `error` — «странный» интерфейс?

## Практика

### Задание 1. Механика

1. Объявите `Shape` с методами `Area() float64` и `Perimeter() float64`. Реализуйте `Rect`, `Circle`. Напишите
   `TotalArea(shapes ...Shape) float64`.
2. Удалите у `Circle` метод `Perimeter` и прочитайте ошибку компиляции дословно.
3. Добавьте проверку реализации на этапе компиляции: `var _ Shape = (*Rect)(nil)`. Объясните, как она работает.
4. Реализуйте `Shape` методами с получателем-указателем и попробуйте присвоить в `Shape` значение, а не указатель.
   Объясните ошибку (method set).
5. Реализуйте `fmt.Stringer` для `Rect` и посмотрите, как изменился вывод `fmt.Println(rect)`.

### Задание 2. nil-ловушка

```go
type MyErr struct{}
func (*MyErr) Error() string { return "boom" }

func do(fail bool) error {
    var e *MyErr
    if fail { e = &MyErr{} }
    return e
}
```

1. Что выведет `fmt.Println(do(false) == nil)`? Прогноз, затем запуск.
2. Выведите `fmt.Printf("%T %v\n", err, err)` и объясните результат в терминах «пара (тип, значение)».
3. Исправьте `do` так, чтобы она возвращала настоящий `nil`.

### Задание 3. Приведение типов и type switch

1. Напишите `Describe(v interface{}) string`, возвращающую разный текст для `int`, `string`, `[]int`, `error`,
   `fmt.Stringer`, `nil` и «всего остального».
2. Вызовите `v.(string)` для значения с `int` внутри — получите панику. Перепишите с `ok`.
3. Опциональное поведение: функция принимает `io.Reader` и, если он ещё и `io.Closer`, закрывает его по завершении.

### Задание 4. Интерфейсы стандартной библиотеки

1. Отсортируйте `[]Person` по возрасту, реализовав `sort.Interface` (`Len`, `Less`, `Swap`). Затем то же через `sort.Slice`.
2. Тип `Money` (копейки в `int64`) должен сериализоваться в JSON как строка `"12.34"` и читаться обратно — реализуйте
   `json.Marshaler` и `json.Unmarshaler`.
3. Напишите `CountingWriter`, оборачивающий любой `io.Writer` и считающий записанные байты. Используйте его с
   `os.Stdout` и `bytes.Buffer`.
4. Напишите `UpperReader`, оборачивающий `io.Reader` и переводящий текст в верхний регистр; скопируйте через `io.Copy`.

### Задание 5. Интерфейс на стороне потребителя (главное задание)

Постройте мини-проект из трёх пакетов:

```
internal/
  storage/     // конкретный тип Storage с ~8 методами: CreateUser, GetUser, UpdateUser, DeleteUser,
               // ListUsers, CreateOrder, GetOrder, ListOrdersByUser (хранение в map)
  userservice/ // бизнес-логика пользователей
  orderservice // бизнес-логика заказов
cmd/app/main.go
```

Требования:

1. В `storage` **нет ни одного интерфейса**; конструктор возвращает `*Storage`.
2. `userservice` и `orderservice` объявляют собственные маленькие интерфейсы — только с теми методами, которые
   реально вызывают.
3. `main` создаёт `*storage.Storage` и передаёт его в оба сервиса.
4. Напишите юнит-тесты для `orderservice` с ручным моком (структура с полями-функциями), не импортируя `storage`
   в тестовой логике.
5. Ответьте письменно: от какого пакета всё-таки зависят оба сервиса и почему? (Подсказка: типы `User`, `Order`.)
   Вынесите типы в пакет `model` и нарисуйте граф зависимостей до и после.

### Задание 6. Границы утиной типизации

Проверьте каждое утверждение лектора компилятором и сохраните тексты ошибок:

1. `var rw io.ReadWriter; var r io.Reader = rw` — компилируется?
2. `var rws []io.ReadWriter; var rs []io.Reader = rws` — компилируется? Напишите функцию-конвертер.
3. `func f() io.ReadWriter` присвоить в `var g func() io.Reader` — компилируется?
4. Интерфейс `A` с методом `Get() io.Reader` и тип с методом `Get() *os.File` — реализует ли тип интерфейс?
5. Перепишите пункт 2 с дженериками (Go 1.18+): `func ReadAll[T io.Reader](rs []T)`. Что изменилось по сравнению с
   тем, что было доступно лектору?

### Задание 7. Чужой тип

Нужно, чтобы `time.Duration` выводился в JSON как строка `"1m30s"`, а `[]string` реализовывал `fmt.Stringer`,
соединяя элементы запятой. Дописать методы чужим типам нельзя — решите через собственные типы.

### Задание 8. Рефакторинг

Возьмите код:

```go
package repo

type Repository interface { /* 15 методов */ }
type repository struct{ db *sql.DB }
func New(db *sql.DB) Repository { return &repository{db: db} }
```

Перепишите его «по Подольскому» и запишите по пунктам, что изменилось в графе зависимостей, в размере моков и в том,
что видит потребитель. Затем запишите контраргументы — в каких случаях исходный вариант оправдан.

## Критерии готовности

- Можете объяснить nil-ловушку через внутреннее устройство интерфейса.
- В задании 5 сервисы тестируются моками из 2–3 методов и не знают о существовании `storage`.
- Можете назвать три ограничения интерфейсов Go и для каждого — обходной путь.
- Формулируете, зачем в вашем коде каждый интерфейс: развязка пакетов, тестируемость или полиморфизм.
